# Аким на 5 часов

MVP симулятора управления Астаной на Python 3.10+. Все 5 районов, 10 показателей,
веса и 14 мероприятий заданы в `city_simulator.py` по спецификации.
Зависимости и API-ключи не нужны. Это учебная модель, а не прогноз реальных изменений.

## Запуск

```bash
python city_simulator.py --self-check
python city_simulator.py --plan example_plan.json
python city_simulator.py --plan example_plan.json --prompt
python -m unittest -v
```

Без аргументов запускается контрольный пример. `--self-check` дополнительно проверяет
стоимость 95 и близость Score к 56.5. Результат выводится как JSON.
Ошибки ввода возвращаются как JSON с `valid: false`, массивом `errors` и кодом выхода 1.
Ошибки аргументов командной строки имеют стандартный код выхода 2.

## Формат плана и Python API

План — JSON-массив ровно из 5 объектов. Для районной меры обязателен `district`
с точным именем района. У городской меры поле отсутствует или равно `null`;
строка `"город"` не принимается. Неизвестные поля запрещены.

```python
from city_simulator import CitySimulator, PlanValidationError

simulator = CitySimulator()
plan = [
    {"measure_id": "M7", "district": "Нура"},
    {"measure_id": "M8", "district": "Нура"},
    {"measure_id": "M10", "district": "Нура"},
    {"measure_id": "M12"},
    {"measure_id": "M5", "district": "Сарыарка"},
]

try:
    result = simulator.simulate(plan)
    print(result["total_cost"])        # 95
    print(result["result"]["score"])   # 56.54307 (с точностью float)
    prompt = simulator.build_report_prompt(result)
except PlanValidationError as error:
    print(error.to_dict())
```

`validate_plan(plan)` проверяет структуру и бизнес-правила и возвращает кортеж
`Selection`. `simulate(plan)` всегда сначала вызывает валидацию. Можно также
передавать список экземпляров `Selection(measure_id, district=None)`.
Некорректный план не рассчитывается; исключение содержит все обнаруженные нарушения.

## Правила и расчет

- Ровно 5 уникальных мероприятий, стоимость ≤ 100, максимум 2 из одного направления.
- M1 и M3 несовместимы в любых районах; M4/M7 и M5/M13 — в одном районе.
- Эффект меры умножается на `(8 - lag) / 8`. Городская мера применяется ко всем
  районам в полном объеме; доля населения не уменьшает ее эффект.
- Фиксированные синергии M1/M2 → T1 +2, M10/M12 → B1 +2, M5/M6 → E2 +2
  применяются в районе первой меры и не масштабируются лагом.
- После сложения всех эффектов и синергий показатели ограничиваются диапазоном
  `[0, 100]`. Отрицательные эффекты сохраняются.
- Балл района: `D_d = sum(w_k * I'_dk)`; средний балл: `D_avg = sum(pop_d * D_d)`.
- `N_crit` считает пары «район, показатель» строго ниже 40.
- `Score = 0.7 * D_avg + 0.3 * min(D_d) - N_crit`.

Вычисления используют `float` без промежуточного округления. Каждый запуск начинается
с исходных показателей. Определения показателей сверх кодов T1–C2 не предполагаются.

JSON содержит `baseline` и `result` с баллами и критическими парами; `districts`
содержит исходные и конечные значения, фактические дельты после ограничения диапазона,
вклады мероприятий и синергий. `selected_measures` и `synergies` объясняют расчет.

## Проверочный пример

| Величина | До | После |
| --- | ---: | ---: |
| D_avg | 56.8624 | 58.0776 |
| Минимальный балл района (Нура) | 49.18 | 52.9625 |
| N_crit | 2 | 0 |
| Astana Quality of Life Score | 52.55768 | **56.54307** |

Стоимость — **95**, остаток — **5**. Прирост Score — **3.98539**.
В Нуре S1 растет с 38 до 48, S2 — с 35 до 43.75; синергия M10/M12 добавляет B1 +2.

## Промпт для LLM

`build_report_prompt(result)` возвращает `messages` (system/user) и `report_schema`.
Сообщение пользователя содержит полный JSON расчета; системное сообщение задает
роль аналитика, требования к точности и запрет на выдуманные факты.

Схема ответа:

```json
{
  "summary": "Краткий итог с бюджетом, Score и N_crit",
  "strengths": ["Сильные стороны с районами, кодами показателей и дельтами"],
  "risks": ["Риски, подтвержденные расчетом"],
  "recommendation": "Приоритет следующего планирования"
}
```

Адаптер выбранного LLM-провайдера должен передать сообщения и схему в поддерживаемом
им формате, проверить ответ на соответствие схеме и отобразить текстовые поля.
В этом MVP сетевой вызов не выполняется: LLM объясняет результат, а все числа
и проверка допустимости плана остаются ответственностью `CitySimulator`.
