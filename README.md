# Аким на 5 часов

Игровой диспетчерский центр со стилизованной интерактивной картой Астаны, вдохновлённый Dispatch.
Главный экран — город в наклонной проекции: Есиль, мосты, дороги, кварталы, парки и узнаваемые ориентиры.
Вы изучаете проблемы жителей, размещаете пять проектов и наблюдаете изменения за восемь кварталов.

Python 3.10+. Все 5 районов, 10 показателей,
веса и 14 мероприятий заданы в `city_simulator.py` по спецификации.
Для локальной симуляции зависимости и API-ключи не нужны. AI-объяснение подключается отдельно.
Это учебная модель, а не прогноз реальных изменений.

## Веб-приложение

```bash
python app.py
```

Откройте **http://127.0.0.1:8000**. Другой порт: `python app.py --port 8080`.
Приложение использует только стандартную библиотеку Python; интернет для интерфейса не нужен.

- Локальная SVG-карта: масштабирование, перетаскивание, hover и выбор района/проблемы.
- Объёмные кварталы, Бәйтерек, Хан Шатыр, условные Акорда и арена; движущийся транспорт.
- Пять игровых районов, максимум две приоритетные проблемы каждого района.
- Досье района с десятью показателями, проектами и синтетическими обращениями.
- Журнал обращений → нужная категория инициатив → ручной выбор меры и района.
- Пять карточек проектов снизу; бюджет и валидация до запуска плюс проверка сервером.
- Кнопка «Запустить симуляцию» и анимация Q1–Q8. Проект включается с квартала L+1.
- После Q8 — настоящий Score, изменения показателей и статусы обращений.
- Синтетические реакции жителей и пресс-конференция с ответом игрока.
- Альтернативная временная линия: лучшая допустимая замена одной меры, посчитанная Python.
- Переключение сценария меняет проекты, районные оценки, обращения и Score на карте.
- Импорт/экспорт JSON и автосохранение черновика в localStorage браузера.

Кнопка «Заново» очищает план и результаты. Изменение любой меры возвращает экран к исходным данным.
Невалидный набор показывает причины ошибок; запуск заблокирован.
Квартальная анимация иллюстративная: промежуточные официальные Score не рассчитываются.
Геометрия и границы условные, это компактная игровая карта, а не настоящий GIS Астаны.

### AI-объяснение (опционально)

На сервере задайте переменные окружения в PowerShell, затем запустите приложение:

```powershell
$env:OPENAI_API_KEY = 'ваш-ключ'
$env:LLM_MODEL = 'идентификатор-доступной-вам-модели'
$env:LLM_BASE_URL = 'https://api.openai.com/v1'
python app.py
```

Используется Chat Completions API с `response_format: json_schema` и строгой схемой.
Выбранная модель и совместимый провайдер должны поддерживать этот формат.
Реализация сверена с [официальной документацией Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).
Ключ не передаётся браузеру и не сохраняется в планах. Поддерживается также `LLM_API_KEY`
(имеет приоритет). `.env.example` содержит образец; `.env` автоматически не читается.
Сетевые запросы выполняются по кнопкам генерации обращений, реакций и обратной связи журналиста.
AI меняет только тексты; районы, связь с показателями, severity, статусы и числовые результаты
задаются Python. Пресс-конференция оценивает аргументацию и не влияет на Score.
При отсутствии настроек, таймауте, отказе модели или неверной структуре ответа
приложение использует локальные шаблоны с явной пометкой источника.
Схема проверяет структуру ответа, но не гарантирует фактическую точность текста LLM;
числа в таблицах всегда поступают из Python-симулятора.

Сервер предназначен для локального демо и по умолчанию слушает только `127.0.0.1`.
Для публичной эксплуатации потребуются production-сервер, HTTPS, авторизация и лимиты AI-запросов.

### Сценарий демонстрации на 2 минуты

1. Нажмите красный маркер школы или медицины в Нуре. Прочитайте обращение.
2. Перейдите к инициативам: автоматически выбран раздел «Соцсфера», решение принимает игрок.
3. Для быстрого показа нажмите «Демо-план»: пять проектов, бюджет 95/100.
4. Запустите симуляцию. Проекты последовательно активируются; после Q8 Score = 56.54.
5. Школы Нуры: 38 → 48, медицина: 35 → 43.75. Старые обращения помечены «Улучшено».
6. Прочитайте реакции жителей и ответьте журналисту в итоговой панели.
7. Откройте альтернативную линию, сравните выигравшие и проигравшие районы.
8. Переключайте «Моя Астана» / «Альтернативная» и наблюдайте изменения проектов на карте.

### Структура

`city_simulator.py` — математика и правила; `app.py` — HTTP API и запуск;
`presentation.py` — названия показателей, сравнение и объяснения;
`reports.py` — общий AI-транспорт и прежний API отчёта;
`city_game.py` — критичность, обращения, реакции и перебор альтернатив;
`game_ai.py` — структурированные тексты AI с резервными шаблонами;
`static/city-map.js` — SVG-геометрия, здания, слои, маркеры и камера;
`static/app.js` — состояния игры, панели, выбор решений и анимация;
`test_city_simulator.py`, `test_app.py`, `test_city_game.py` — 38 проверок.

Frontend и backend запускаются одной командой `python app.py`; сборка и npm не нужны.
Существующий HTTP-сервер стандартной библиотеки сохранён, миграция на FastAPI не выполнялась.

### API

Все POST-запросы используют `Content-Type: application/json`. В `plan` передаётся
тот же массив решений, что в `example_plan.json`; сервер заново проверяет и рассчитывает его.

| Маршрут | Назначение |
| --- | --- |
| `GET /api/catalog` | Данные города, каталог, исходный Score и обращения |
| `POST /api/validate` | `{plan}` → проверка допустимости, без результата симуляции |
| `POST /api/simulate` | `{plan}` → result, report, appeals, aftermath |
| `POST /api/alternative` | `{plan}` → лучшая допустимая замена одной меры и сравнение |
| `POST /api/ai/appeals` | `{}` или `{plan}` → синтетические обращения |
| `POST /api/ai/result` | `{plan}` → реакции, вопрос журналиста, краткий итог |
| `POST /api/ai/feedback` | `{plan, answer}` → отзыв на аргументацию игрока |
| `POST /api/compare` | `{plan, reference}` → числовое сравнение двух планов |
| `POST /api/report` | `{plan, reference?}` → прежний структурированный отчёт |

Критичность: `<40` critical, `[40,50)` high, `[50,60)` medium, `>=60` normal.
При улучшении обращения сохраняют ID и исходное значение. «Улучшено» не означает «в норме»:
текущая критичность также остаётся видимой. Все жители вымышлены, их тексты не являются
реальными обращениями или результатом соцопроса.

```bash
python city_simulator.py --self-check
python city_simulator.py --plan example_plan.json
python city_simulator.py --plan example_plan.json --prompt
python -m unittest -v
```

Без аргументов запускается контрольный пример. `--self-check` дополнительно проверяет

Ошибки ввода возвращаются как JSON с `valid: false`, массивом `errors` и кодом выхода 1.

## Формат плана и Python API

План — JSON-массив ровно из 5 объектов. Для районной меры обязателен `district`
с точным именем района. У городской меры поле отсутствует или равно `null`;
строка `"город"` не принимается. Неизвестные поля запрещены.

```python
from city_simulator import CitySimulator, PlanValidationError

simulator = CitySimulator()
plan = [
    {"measure_id": "M7", "district": "Нура"},
    {"measure_id": "M8", "district": "Нура"},
    {"measure_id": "M10", "district": "Нура"},
    {"measure_id": "M12"},
    {"measure_id": "M5", "district": "Сарыарка"},
]

try:
    result = simulator.simulate(plan)
    print(result["total_cost"])        # 95
    print(result["result"]["score"])   # 56.54307 (с точностью float)
    prompt = simulator.build_report_prompt(result)
except PlanValidationError as error:
    print(error.to_dict())
```

`validate_plan(plan)` проверяет структуру и бизнес-правила и возвращает кортеж
`Selection`. `simulate(plan)` всегда сначала вызывает валидацию. Можно также
передавать список экземпляров `Selection(measure_id, district=None)`.
Некорректный план не рассчитывается; исключение содержит все обнаруженные нарушения.

## Правила и расчет

- Ровно 5 уникальных мероприятий, стоимость ≤ 100, максимум 2 из одного направления.
- M1 и M3 несовместимы в любых районах; M4/M7 и M5/M13 — в одном районе.
- Эффект меры умножается на `(8 - lag) / 8`. Городская мера применяется ко всем
  районам в полном объеме; доля населения не уменьшает ее эффект.
- Фиксированные синергии M1/M2 → T1 +2, M10/M12 → B1 +2, M5/M6 → E2 +2
  применяются в районе первой меры и не масштабируются лагом.
- После сложения всех эффектов и синергий показатели ограничиваются диапазоном
  `[0, 100]`. Отрицательные эффекты сохраняются.
- Балл района: `D_d = sum(w_k * I'_dk)`; средний балл: `D_avg = sum(pop_d * D_d)`.
- `N_crit` считает пары «район, показатель» строго ниже 40.
- `Score = 0.7 * D_avg + 0.3 * min(D_d) - N_crit`.

Вычисления используют `float` без промежуточного округления. Каждый запуск начинается
с исходных показателей. Определения показателей сверх кодов T1–C2 не предполагаются.

JSON содержит `baseline` и `result` с баллами и критическими парами; `districts`
содержит исходные и конечные значения, фактические дельты после ограничения диапазона,
вклады мероприятий и синергий. `selected_measures` и `synergies` объясняют расчет.

## Проверочный пример

| Величина | До | После |
| --- | ---: | ---: |
| D_avg | 56.8624 | 58.0776 |
| Минимальный балл района (Нура) | 49.18 | 52.9625 |
| N_crit | 2 | 0 |
| Astana Quality of Life Score | 52.55768 | **56.54307** |

Стоимость — **95**, остаток — **5**. Прирост Score — **3.98539**.
В Нуре S1 растет с 38 до 48, S2 — с 35 до 43.75; синергия M10/M12 добавляет B1 +2.

## Промпт для LLM

`build_report_prompt(result)` возвращает `messages` (system/user) и `report_schema`.
Сообщение пользователя содержит полный JSON расчета; системное сообщение задает
роль аналитика, требования к точности и запрет на выдуманные факты.

Схема ответа:

```json
{
  "summary": "Краткий итог с бюджетом, Score и N_crit",
  "strengths": ["Сильные стороны с районами, кодами показателей и дельтами"],
  "risks": ["Риски, подтвержденные расчетом"],
  "recommendation": "Приоритет следующего планирования"
}
```

Адаптер выбранного LLM-провайдера должен передать сообщения и схему в поддерживаемом
им формате, проверить ответ на соответствие схеме и отобразить текстовые поля.
Консольный `--prompt` только выводит сообщения. Веб-приложение вызывает AI через `reports.py`:
LLM объясняет результат, а все числа и проверка допустимости плана
остаются ответственностью `CitySimulator`.
